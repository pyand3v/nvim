# Neovim configuration

Lua configuration managed with lazy.nvim, with LSP completion, Tree-sitter,
format-on-save, Telescope navigation, Git tools, and C/C++ debugging through CodeLLDB.

## Setup

Requires Neovim 0.12+ and mise. Place this checkout at `~/.config/nvim`, then on Ubuntu:

```sh
./scripts/install.sh --apt
```

The installer uses mise to install pinned Node, npm, Go, and Rust versions. Omit `--apt` if system prerequisites are already installed. See the
[setup guide](docs/setup.md) for requirements, version pinning, updates, and limits
of reproducibility. See the [runbook](docs/runbook.md) for keymaps, debugging, and
language-specific workflows.

## Layout

- `init.lua`: entry point.
- `lua/config/`: shared editor behavior; `lsp/` contains LSP configuration.
- `lua/config/tools.lua`: versioned Mason tool manifest.
- `lua/plugins/{ui,navigation,editing,coding}/`: focused lazy.nvim plugin specs.
- `scripts/`: Ubuntu provisioning and Mason version verification.
- `docs/`: setup and daily usage.
- `.github/`: CI, startup checker, and contribution templates.
- `lazy-lock.json`: plugin revisions.

`lua/config/theme.lua` is generated by the theme picker. Windows remain transparent
after theme changes. Plugin update checks run in the background; Mason package
installation is explicit. See [AGENTS.md](AGENTS.md) for repository conventions.

## Distribution

Publish this repository as a versioned Git release or source archive, including the
lockfiles, `mise.toml`, `scripts/`, and `docs/`. Recipients place it at their Neovim
config path and follow the setup guide. For parallel installs, use a separate
`NVIM_APPNAME` and matching config directory. An Ubuntu `.deb` or container image
is possible for managed deployments, but requires separate packaging, dependency
management, and update testing; neither is provided here.
